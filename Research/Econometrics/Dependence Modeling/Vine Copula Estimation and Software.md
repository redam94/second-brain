# Vine Copula Estimation and Software

> [!summary]
> Vine copulas are fitted by **sequential maximum likelihood**: marginals first, then pair copulas tree-by-tree using pseudo-observations generated by h-functions. Full joint MLE is computationally feasible but rarely necessary — the sequential estimator is consistent and nearly efficient. The **VineCopula** R package (Schepsmeier, Stoeber, Czado, Nagler et al.) and **pyvinecopulib** Python library (Nagler & Vatter, wrapping the C++ `vinecopulib`) are the standard implementations, supporting automatic structure and family selection via the Dissmann MST algorithm and AIC/BIC.

## Overview

Estimating a vine copula involves three nested choices: marginal distributions, vine structure, and bivariate pair copula families. The standard workflow separates these: (1) estimate marginals independently, (2) use empirical Kendall's $\tau$ to select the vine structure (Dissmann algorithm), (3) select each pair copula family by AIC/BIC, (4) refine with joint MLE if needed. This sequential approach is computationally tractable for $d \leq 50$ and closely approximates the full MLE.

## Main Content

> [!definition] Sequential MLE procedure (Aas et al. 2009, Haff 2013)
> **Inputs:** Data $\mathbf{x} \in \mathbb{R}^{n \times d}$, vine structure $V$, candidate family set $\mathcal{F}$.
>
> **Step 1 — Marginal estimation:**
> For each variable $k$, fit a parametric marginal $\hat{F}_k$ (e.g. normal, $t$, skew-$t$, empirical ECDF). Transform to pseudo-observations: $\hat{u}_{ik} = \hat{F}_k(x_{ik})$, rescaled to $\frac{\text{rank}}{n+1}$ when using the empirical CDF to avoid boundary issues.
>
> **Step 2 — Tree $T_1$ estimation:**
> For each edge $(j,k) \in T_1$: choose family $\hat{f}_{jk} \in \mathcal{F}$ minimising AIC/BIC with MLE parameters $\hat{\boldsymbol{\theta}}_{jk}$. Compute h-function outputs: $\hat{v}_{j|k} = h(\hat{u}_j | \hat{u}_k; \hat{\boldsymbol{\theta}}_{jk})$ and $\hat{v}_{k|j} = h(\hat{u}_k | \hat{u}_j; \hat{\boldsymbol{\theta}}_{jk})$ for use in $T_2$.
>
> **Step 3 — Tree $T_\ell$ estimation ($\ell = 2, \ldots, d-1$):**
> The inputs for each pair copula in $T_\ell$ are the h-function outputs from $T_{\ell-1}$. For edge $(i,j)|\mathbf{v}$: look up $\hat{v}_{i|\mathbf{v}}$ and $\hat{v}_{j|\mathbf{v}}$ from the previous tree's recursion; fit and select family by AIC/BIC; compute h-function outputs for $T_{\ell+1}$.
>
> **Step 4 (optional) — Full joint MLE:**
> Use the sequential estimates as starting values for joint MLE of all pair copula parameters simultaneously. For most applications the sequential estimate is already nearly efficient; full MLE is only worthwhile if the log-likelihood gap is significant.
^def-seqmle

> [!definition] Goodness-of-fit for vine copulas
> The **Rosenblatt transform test** is the standard vine copula GoF approach (Czado et al. 2013):
> 1. Apply the vine copula's conditional CDFs (via h-function recursion) to transform data to an approximately $\text{Uniform}(0,1)^d$ vector.
> 2. Test the transformed vector for multivariate uniformity using the Cramér-von Mises or Kolmogorov-Smirnov statistic.
> 3. P-value via parametric bootstrap (resample from fitted vine, refit, retest).
>
> AIC and BIC compare vine models (different structures, different pair families) on the same data.
^def-gof

> [!definition] Vine copula simulation
> Simulation from a fitted vine follows the inverse of the estimation recursion:
> 1. Draw $\tilde{u}_1, \ldots, \tilde{u}_d \sim \text{Uniform}(0,1)^d$ independently.
> 2. Set $\hat{u}_1 = \tilde{u}_1$.
> 3. For $k = 2, \ldots, d$: apply the inverse h-function $h^{-1}(\tilde{u}_k | \hat{u}_{k-1}; \hat{\boldsymbol{\theta}})$ to recover the copula-correlated pseudo-observation.
> 4. Apply the inverse marginal CDFs: $x_k = \hat{F}_k^{-1}(\hat{u}_k)$.
>
> Simulation is fast (one pass through the vine) and exact given the parametric model.
^def-simulation

> [!definition] VineCopula R package
> `VineCopula` (Schepsmeier, Stoeber, Czado, Graeler, Nagler, Dissmann et al., CRAN).
>
> **Key functions:**
> - `RVineStructureSelect(data, familyset)` — runs Dissmann's MST algorithm tree-by-tree, selects pair copula families by AIC/BIC, returns an `RVineMatrix` object
> - `RVineCopSelect(data, familyset, RVM)` — selects pair copula families for a fixed structure
> - `RVineSeqEst(data, RVM)` — sequential MLE for fixed structure and families
> - `RVineLogLik(data, RVM)` — log-likelihood evaluation
> - `RVineSim(N, RVM)` — simulation from a fitted vine
> - `C2RVine(order, family, par, par2)` — create C-vine `RVineMatrix`
> - `D2RVine(order, family, par, par2)` — create D-vine `RVineMatrix`
> - `BiCopSelect(u1, u2, familyset)` — select a single bivariate copula family
> - `BiCopEst(u1, u2, family)` — MLE for a single bivariate copula
> - `RVineGofTest(data, RVM)` — Rosenblatt transform GoF test
>
> **Supported families (familyset):** 0 = independence, 1 = Gaussian, 2 = $t$, 3 = Clayton, 4 = Gumbel, 5 = Frank, 6 = Joe, 7 = BB1, 8 = BB6, 9 = BB7, 10 = BB8, plus rotations (add 10, 20, or 30 for 90°, 180°, 270° rotation).
^def-vinecopula-r

> [!definition] pyvinecopulib and rvinecopulib (Python/R C++ bindings)
> `vinecopulib` is a high-performance C++ library for vine copulas by Nagler & Vatter. Python bindings: `pyvinecopulib`; R bindings: `rvinecopulib`.
>
> **Advantages over `VineCopula`:** significantly faster for large $d$ (C++ implementation), supports nonparametric (kernel) pair copulas, allows covariate-dependent copulas, PyTorch backend for gradient-based fitting, scikit-learn compatible API.
>
> **Key Python API:**
> ```python
> import pyvinecopulib as pv
>
> # Fit with automatic structure and family selection
> controls = pv.FitControlsVinecop(family_set=[pv.BicopFamily.gaussian, pv.BicopFamily.student],
>                                   trunc_lvl=3)   # truncate at tree 3
> cop = pv.Vinecop(data=u, controls=controls)
>
> # Simulate
> u_sim = cop.simulate(n=1000)
>
> # Log-likelihood
> loglik = cop.loglik(u)
> ```
^def-pyvinecopulib

## Examples

> [!example] Choosing between C-vine, D-vine, and R-vine in practice
> - **C-vine:** A macro-finance application where a "market factor" (e.g. S&P 500 return) is expected to explain most pairwise dependence among assets. Place the market factor as the root in $T_1$; the remaining pair copulas in $T_1$ are $(factor, asset_i)$ — analogous to factor analysis but with flexible copulas.
> - **D-vine:** A time-series of monthly weather variables where January $\to$ February $\to \cdots$ has a natural path ordering. Lag-1 dependence is strongest and appears in $T_1$; lag-2 conditional dependence in $T_2$, etc.
> - **R-vine (Dissmann):** Financial returns on 20 stocks from different sectors, no obvious ordering. Let the data choose: the MST algorithm will group the most correlated pairs in $T_1$, creating a structure that may resemble an industry graph.

> [!example] Vine vs factor copula comparison for financial data
> **Factor copula (Oh & Patton 2017, $N=100$):** 8-block market + industry factor model, 16 parameters; skew $t$-$t$ factor; estimated by SMM in ~minutes.
>
> **Vine copula ($d=20$ stocks):** 190 pair copulas; Dissmann MST + AIC family selection via `RVineStructureSelect`; sequential MLE in seconds per tree; GoF via Rosenblatt bootstrap. Flexible enough to capture heterogeneous pair dependence structures.
>
> **Trade-off:** For $d=100$, vine copulas are over-parameterised without aggressive truncation (truncated to $T^*=2$: 197 pair copulas, still manageable). Factor copulas scale better via parsimony; vine copulas are richer for moderate $d$.
